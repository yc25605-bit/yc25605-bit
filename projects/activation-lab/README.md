# 学习打卡产品：新用户激活分析

> 产品／运营作品练习 · 人工构造数据 · 未上线实验  
> 本案例用于展示分析过程和方案设计，不代表真实公司的数据、用户访谈或个人工作业绩。

## 1. 场景与问题

假设一款面向碎片化学习用户的产品，注册后的路径为：设置学习目标 → 完成首次学习 → 次日回访。运营团队希望在增加拉新投入前，先确认新用户在哪一步流失，并形成可验证的改进方案。

**本次交付**：一份漏斗分析、一版新手引导需求、一套运营动作与实验评估方案。范围限定为新用户首次体验，不涉及付费转化或长期留存结论。

## 2. 数据与指标口径

数据见 [data.json](./data.json)，为虚构的连续七天注册 cohort，总计 3,000 人；所有用户的 D1 观察窗口均已结束。

- 注册：以 user_id 去重的注册成功用户。
- 目标设置：注册后 24 小时内完成目标设置的用户。
- 首次学习：注册后 24 小时内，按上述顺序完成目标设置并完成一节学习的用户；完成事件由服务端判定。
- D1 回访：上述首次学习用户中，在注册次日（统一 UTC+8 自然日）打开产品的用户。
- 激活率 = 首次学习人数 ÷ 注册人数。
- 激活用户 D1 回访率 = D1 回访人数 ÷ 首次学习人数；它不等同于全体注册用户的次日留存率。
- 来源按注册时锁定的最后一次非直接访问渠道归因；本例渠道互斥。

此数据是聚合的顺序漏斗，无法识别具体流失原因，也不能计算全体注册用户的次日留存。

## 3. 漏斗发现

| 来源 | 注册 | 设置目标 | 首次学习 | D1 回访 | 激活率 | 激活用户 D1 回访率 |
|---|---:|---:|---:|---:|---:|---:|
| 内容自然流量 | 1,000 | 750 | 450 | 180 | 45.00% | 40.00% |
| 社群推荐 | 600 | 480 | 360 | 180 | 60.00% | 50.00% |
| 付费投放 | 1,400 | 770 | 308 | 77 | 22.00% | 25.00% |
| **合计** | **3,000** | **2,000** | **1,118** | **437** | **37.27%** | **39.09%** |

| 环节 | 相邻步骤转化率 | 流失人数 |
|---|---:|---:|
| 注册 → 设置目标 | 66.67% | 1,000 |
| 设置目标 → 首次学习 | 55.90% | 882 |
| 首次学习 → D1 回访 | 39.09% | 681 |

**可以支持的判断：**

1. 注册到目标设置流失人数最多，适合作为首次体验优化的候选环节。
2. 付费渠道占注册用户 46.67%，但激活率仅 22%，值得优先核查投放承诺、用户意图与落地体验。
3. 社群来源的激活率和激活用户 D1 回访率更高，但渠道人群并非随机分配，不能据此认定社群触达造成提升。

**仍然未知：**目标设置是否繁琐、课程是否匹配、是否存在加载故障。漏斗只有行为结果，不能替代访谈或性能排查。

## 4. 优先验证的假设

| 假设 | 需要的证据 | 验证动作 |
|---|---|---|
| 用户尚未感知价值，就被要求设置目标 | 目标页停留、退出、错误事件；用户反馈 | 邀请 5–8 名目标页流失用户做探索性访谈，并检查事件日志 |
| 付费素材与首节课不匹配 | 素材版本、落地页与课程主题的分组数据 | 检查主要素材的承诺与实际体验是否一致 |
| 首节课程负担过高 | 开始到完成的耗时与中断位置 | 补充课程开始、进度和完成事件 |

先排除故障，再测试引导改版。访谈数量只是招募计划，不表示已完成访谈，也不足以估计总体比例。

## 5. 产品方案：先体验，再设目标

**假设**：让新用户先完成一节简短体验课，再设置学习目标，可以降低首次行动成本。

### 用户流程

注册成功 → 推荐一节 3 分钟体验课 → 完成学习 → 自愿设置目标 → 自愿开启提醒。

### 最小版本需求

- 注册后首屏突出「开始 3 分钟体验」，展示课程主题和预计耗时。
- 保留「先设置目标」入口，满足已有明确计划的用户。
- 体验完成后再展示目标设置，允许跳过；不自动订阅提醒。
- 请求失败显示重试入口，重复提交不重复记录完成事件。
- 老用户维持原有体验；仅新注册且符合实验条件的用户进入实验。

### 验收条件与埋点

| 事件 | 触发时机 | 关键字段 |
|---|---|---|
| onboarding_view | 新手引导实际展示 | user_id、variant、channel、timestamp |
| lesson_start | 用户开始体验课 | user_id、variant、lesson_id、timestamp |
| lesson_complete | 服务端确认完成 | user_id、variant、lesson_id、event_id、timestamp |
| goal_saved | 目标保存成功 | user_id、variant、timestamp |
| reminder_opt_in | 用户主动开启提醒 | user_id、variant、timestamp |

所有事件均需关联注册时间；实验分组在首次符合条件时固定，跨端保持一致。去重完成事件，校验时间顺序；不在分析数据中存储手机号等直接身份信息。

**关键口径调整**：新方案允许跳过目标设置，因此实验激活率必须按「注册后 24 小时内完成首次学习」统计，不再要求目标设置在前。正式实验需先确认旧路径不存在绕过设置的学习，否则重算基线。

## 6. 运营配套

| 人群 | 动作 | 时机与限制 | 观察指标 |
|---|---|---|---|
| 注册后未开始学习 | 提示体验课主题与预计耗时 | 注册 2 小时后，优先站内提示；外部提醒仅面向已同意用户 | 触达后的课程开始率 |
| 开始但未完成 | 提供继续学习入口 | 下次访问时展示，不重复弹窗 | 继续学习后的完成率 |
| 完成首次学习 | 推荐下一节课并邀请自愿设目标 | 完成页展示一次 | 目标设置率与 D1 回访率 |

触达转化仅用于描述，不能直接当作增量效果。本轮产品 A/B 实验两组保持相同运营策略；后续再通过独立留白对照实验验证触达收益，避免混淆原因。

## 7. 实验与决策

- **分组**：新注册用户按 user_id 1:1 随机固定分组；A 为现有路径，B 为体验优先。
- **主指标**：注册后 24 小时首次学习完成率，分母为全部符合条件并分组的注册用户，包括未打开引导的用户。
- **计划目标**：从模拟基线 37.27% 提升至 42.00%，即约 +4.73 个百分点；是设计目标，不是已有成果。
- **样本量**：使用独立两比例正态近似、双侧 α=0.05、功效 80%，约需每组 1,700 人。真实上线应结合真实基线、分流损耗和业务条件重新估算。
- **周期**：至少覆盖两个完整周周期，达到计划样本且最后一批用户完成 24 小时及 D1 观察后统一分析；流量不足则延长，不用早期波动宣布胜出。
- **护栏**：监控崩溃率、课程加载失败率、提醒退订／投诉，以及全体注册用户 D1 留存。正式上线前确定容忍阈值并校验对应埋点。
- **分析**：检查分组比例异常、事件漏报及两组渠道构成；报告绝对提升、相对提升与 95% 置信区间。
- **决策**：主指标显著改善且护栏通过，才分阶段放量；结果不确定则记录区间并继续诊断，不宣称方案有效。

激活用户 D1 回访率可辅助观察，但实验会改变激活人群构成，因此不能单独作为留存改善的因果证据。全体注册用户 D1 留存需要额外采集所有注册用户的回访事件。

## 8. 情景测算与局限

如果同样 3,000 名注册用户的激活率达到 42%，激活人数为 1,260，相比本例增加 **142 人**。这是固定注册规模下的情景测算，不是实验预测或真实收益。

缺少渠道成本、收入和长期留存数据，无法判断获客回报，也不据此建议削减或增加预算。未执行真实访谈、产品开发和 A/B 实验，当前交付止于可复核分析与待验证方案。

## 9. 复现分析

使用 Python 3，无需安装第三方依赖。在仓库根目录运行：

```bash
python projects/activation-lab/analyze.py
```

脚本读取同目录模拟数据，校验非负人数与顺序漏斗关系，输出各渠道指标、阶段流失和情景测算；分母为零时显示 N/A。
